# Tournament Failure Modes – Quick Matrix

This file summarizes **tournament‑specific failure modes** and how they surface to the user.

For full details, see:

- `TournamentNetworkFlow.md`
- `TournamentMatchmaking.md`
- `TournamentMatchFlow.md`
- `FailureModesAndUX.md`

---

## 1. Tournament control‑plane failures (matchmaking + backend)

| Scenario                                                   | Wire signal (matchmaking/backend)                                                                                                                                                                                                                    | User‑facing behavior                                                                                                                                                            |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create tournament while already in one                     | `ERROR` on `/matchmaking` with `code: 'TOURNAMENT_LIMIT'` and message like “You already have a tournament in progress”                                                                                                                               | Snackbar error; current active tournament is restored in UI (lobby + bracket).                                                                                                  |
| Join invalid/missing tournament                            | `ERROR` with `code: 'TOURNAMENT_INVALID'` or `code: 'TOURNAMENT_API'` (e.g. 404/400 from backend)                                                                                                                                                    | Snackbar (“Tournament identifier is invalid” or generic failure); user stays on tournaments list.                                                                               |
| Backend tournament API failure (create/join/leave/forfeit) | `ERROR` with `code: 'TOURNAMENT_API'` and a descriptive message                                                                                                                                                                                      | Snackbar; tournament state may stay stale until next successful refresh.                                                                                                        |
| Leaving or forfeiting tournament                           | HTTP `DELETE`/`PATCH` succeeds; matchmaking cancels any pending countdowns and sends `TOURNAMENT_MATCH_COUNTDOWN` with `status: 'cancelled', reason: 'forfeited'`, then refreshes state (`TOURNAMENT_LOBBY_UPDATED` + `TOURNAMENT_BRACKET_SNAPSHOT`) | Bracket updates (participant marked `forfeited`, opponent may advance); countdown UI disappears; user sees updated tournament status, plus any snackbar configured in handlers. |
| Tournament WS connection lost (matchmaking socket)         | `/matchmaking` WebSocket closes abnormally (non‑1000/1001/1005); `useTournamentConnection` treats it as error                                                                                                                                        | Snackbar (“Tournament connection lost. Reconnecting…”); hook automatically reconnects and re‑syncs lobby + bracket when back.                                                   |

## 2. Scheduled matches and countdown failures

| Scenario                                                         | Wire signal (tournament messages)                                                                                                                                                                          | User‑facing behavior                                                                                                                                                                    |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Match ready but one player offline                               | `TOURNAMENT_MATCHES_READY` may still be sent; countdown started; availability check fails at execution → `TOURNAMENT_MATCH_COUNTDOWN` with `status: 'cancelled', reason: 'offline'` and reminder scheduled | Countdown bar disappears; no match handoff occurs; after backend auto‑forfeit (if configured), bracket refresh shows winner advanced without playing.                                   |
| Player disconnects during countdown                              | `handleClientDisconnectFromTournament` cancels countdown and sends `TOURNAMENT_MATCH_COUNTDOWN` with `status: 'cancelled', reason: 'offline'`; reminder scheduled                                          | Countdown UI stops; later, when the player reconnects, they may receive a fresh `TOURNAMENT_MATCHES_READY` and new countdown, or the match may auto‑resolve depending on absence rules. |
| Participant leaves or forfeits tournament while match is pending | `handleLeaveTournament` / `handleForfeitTournament` cancels countdown with `reason: 'forfeited'`, clears reminders, then calls state sync → `TOURNAMENT_LOBBY_UPDATED` + `TOURNAMENT_BRACKET_SNAPSHOT`     | Countdown/UI for that match disappears; bracket updates show the remaining participant advancing (or match resolved by forfeit).                                                        |
| Absence auto‑win after countdown and absence window              | `scheduleAbsenceAutoWin` calls backend `auto-forfeit`; then `handleTournamentStateUpdated` triggers sync → `TOURNAMENT_LOBBY_UPDATED` + `TOURNAMENT_BRACKET_SNAPSHOT` (no dedicated WS error)              | From the UI, the match never starts; after some delay, the bracket simply updates with one player advanced and the other marked forfeited.                                              |

## 3. Tournament match handoff and in‑game failures

| Scenario                                                        | Wire signal (handoff / game)                                                                                                                                                                                                        | User‑facing behavior                                                                                                                                                                                                                 |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Allocator fails to create tournament match room                 | `ERROR` on `/matchmaking` with `code: 'ALLOCATOR'` during `createMatch` with `tournament` context; no `HANDOFF` is sent                                                                                                             | Snackbar (“No available game servers right now. Please try again shortly.”); tournament UI remains, bracket unchanged; match may be retried via scheduler/reminders.                                                                 |
| Tournament match handoff timeout                                | `HANDOFF_TIMEOUT` message for the room, or no `HANDOFF` within scheduler expectations (handled by `handleHandoffTimeout`)                                                                                                           | Tournament UI sees no in‑game handoff; depending on handlers, user either sees an error snackbar or just a refreshed bracket/lobby state after backend resolves the match.                                                           |
| Game connection fails / join token invalid for tournament match | Game WS closes with permanent close code (e.g. `ROOM_NOT_FOUND`, `INVALID_TOKEN`, `MATCH_FINISHED`, `SERVER_ERROR`); `connectOnline`/reconnector treat as terminal and emit synthetic `MATCH_END` with reason `'connection_closed'` | Tournament match view shows connection error and exits back to tournament detail; `useMatchLifecycle` triggers `refreshTournamentState`, and bracket updates based on backend’s view (match may be replayed or resolved externally). |
| Opponent disconnects and never returns during tournament match  | Game server uses tournament reconnect grace; on expiry, sends `MATCH_END` with reason `'opponent_timeout'` and reports result to backend tournament APIs                                                                            | Tournament match UI shows “Opponent disconnected” (or equivalent), then returns to tournament page; subsequent state sync updates the bracket with the winner advanced.                                                              |
| You quit/forfeit from a tournament match                        | Client sends `{ type: 'forfeit' }` on game WS; game server sends `MATCH_END` with reason `'forfeit'` and updates tournament result; matchmaking triggers `TOURNAMENT_*` state sync                                                  | Tournament match UI shows a forfeit snackbar and exits to tournament detail; bracket updates show you eliminated or your opponent advanced.                                                                                          |
